# Warehouse Tracker
## Coding Standards and Process Standards

### 1. Coding Standards

These are the basic rules we all follow when writing code for our project.

- Use clear and understandable names for variables, functions, and classes.
- Use lowercase letters and underscores for variable and function names (snake_case).
- Use capital letters at the beginning of class names (PascalCase).
- Use 4 spaces for indentation.
- Keep the code simple, clean, and easy to understand.
- Add comments when necessary to explain parts of the code.
- Avoid repeating the same code unnecessarily.
- Test your code before uploading it to GitHub.
- Make sure your code works with the rest of the project.

### 4. GitHub Rules

- All team members must work on their own branches.
- Nobody should directly change the main branch.
- Before uploading code, check that it works correctly.
- Every member must commit their work with clear messages.
- Commit messages should explain what was changed (for example: "Add product class").
- Each member must make at least two commits for their assigned work.
- Push your changes to your own branch.
- Do not merge branches into main unless the team and teacher give permission.

### 5. Communication and Teamwork

- Keep the team updated about your progress.
- Inform the team if you face any problems.
- Ask before changing another member's code.
- Help each other when needed.
- Complete assigned tasks on time.
- Discuss major changes together before implementing them.

### 6. General Rules

Our goal is to keep the project organized, make the code easy to understand, and work together as a team.

Everyone is responsible for their own work and for making sure it follows these standards.
